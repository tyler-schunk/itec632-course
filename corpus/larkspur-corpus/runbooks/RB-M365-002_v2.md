# RB-M365-002 Shared mailbox and calendar permissions

## Purpose / When to use

Use when a client asks to give someone access to a shared mailbox (info@, frontdesk@, billing@), create a new shared mailbox, give send-as or send-on-behalf rights, or share/delegate a calendar (for example, an assistant managing a partner's calendar at Dunmore & Pace, or a front desk managing provider calendars).

## Authorization

Access to someone else's mail or calendar must be approved by an **authorized contact** in Harbor PSA, or by the mailbox owner for their own calendar. A coworker asking for access to another person's mailbox is not enough. Record the approver.

## Prerequisites / access needed

- Exchange admin center via GDAP (Exchange Administrator)
- Exchange Online PowerShell (`Connect-ExchangeOnline`)

## Permission types (know the difference)

| Permission | What it does |
|---|---|
| **Full Access** | Open and read the mailbox. With automapping, it appears in classic Outlook automatically. Does not allow sending as the mailbox. |
| **Send As** | Mail appears to come from the mailbox itself. |
| **Send on Behalf** | Mail shows "User on behalf of Mailbox". |
| **Calendar folder permission** | Reviewer (read), Editor (read/write), or Delegate (Editor plus receives meeting requests). |

## Steps

### A. Create a shared mailbox

1. EAC > **Recipients > Mailboxes > Add a shared mailbox**. Display name, email address, domain.
2. Add members (gives Full Access and Send As by default in the wizard). No license needed under 50 GB.
3. Block sign-in on the shared mailbox's user object (M365 admin center > Users > select > Block sign-in). Shared mailboxes should never be signed into directly.

### B. Grant access to an existing shared mailbox

1. Confirm approval.
2. EAC > Recipients > Mailboxes > select mailbox > **Delegation** > edit **Read and manage (Full Access)**, **Send as**, or **Send on behalf**.
3. PowerShell:
   ```powershell
   Add-MailboxPermission -Identity frontdesk@client.example -User jdoe@client.example -AccessRights FullAccess -InheritanceType All -AutoMapping $true
   Add-RecipientPermission -Identity frontdesk@client.example -Trustee jdoe@client.example -AccessRights SendAs -Confirm:$false
   Set-Mailbox frontdesk@client.example -GrantSendOnBehalfTo @{Add="jdoe@client.example"}
   ```
4. Automapped mailboxes show up in classic Outlook within about 60 minutes; restarting Outlook helps. **New Outlook and Outlook on the web do not automap**: the user adds it via right-click on **Shared with me** > **Add shared folder or mailbox** (new Outlook) or **Add shared folder** (OWA).
5. For Send As in classic Outlook, the user must add the **From** field (Options > Show Fields > From) and pick the shared address.
6. Sent items: by default, mail sent as the shared mailbox lands in the sender's Sent Items. Most clients want copies in the shared mailbox:
   ```powershell
   Set-Mailbox frontdesk@client.example -MessageCopyForSentAsEnabled $true -MessageCopyForSendOnBehalfEnabled $true
   ```

### C. Remove access

```powershell
Remove-MailboxPermission -Identity frontdesk@client.example -User jdoe@client.example -AccessRights FullAccess -Confirm:$false
Remove-RecipientPermission -Identity frontdesk@client.example -Trustee jdoe@client.example -AccessRights SendAs -Confirm:$false
```
Classic Outlook can take a while to drop an automapped mailbox; restart Outlook. If it persists, rebuild the profile (RB-M365-003).

### D. Calendar permissions

1. Check existing:
   ```powershell
   Get-MailboxFolderPermission -Identity partner@client.example:\Calendar
   ```
2. Add:
   ```powershell
   Add-MailboxFolderPermission -Identity partner@client.example:\Calendar -User assistant@client.example -AccessRights Editor
   ```
   Use `Set-MailboxFolderPermission` if the user already has an entry (Add fails if one exists).
3. Delegate with meeting requests:
   ```powershell
   Add-MailboxFolderPermission -Identity partner@client.example:\Calendar -User assistant@client.example -AccessRights Editor -SharingPermissionFlags Delegate
   ```
   Then decide with the client whether meeting requests go to the delegate only or both (set in the owner's Outlook: File > Account Settings > Delegate Access, or in new Outlook Settings > Calendar > Shared calendars).
4. Default org-wide visibility: the **Default** entry is usually AvailabilityOnly. Only change it with client approval.
5. Room and equipment mailboxes: use `Set-CalendarProcessing` for booking rules; escalate if the client wants approval workflows.

## Priority guidance

- Standard access request: **P4**.
- User covering for an absent coworker today and blocked from a key shared mailbox (front desk, orders): **P3**.
- Shared mailbox inaccessible for everyone: **P2**.

## Escalate if

- The request is to access a specific person's mailbox for HR, legal, or investigation reasons: Renee Castillo before granting.
- Permissions look correct but the user still cannot open the mailbox after 2 hours and a profile rebuild: Renee Castillo.
- Hybrid tenant with on-prem mailboxes: Renee Castillo.
